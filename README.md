# Craft World — ตารางกำไรการผลิต (Profit Matrix)

เว็บแอป Next.js ที่ตอบคำถามเดียว: **ซื้อวัตถุดิบจากตลาด → ผลิต → ขายผลผลิต คุ้มไหม และเลเวลไหนดีที่สุด**
ครอบคลุมโรงงานทั้ง 43 ตัวใน Craft World ตั้งแต่ Lv.1 ถึงเลเวลสูงสุดของแต่ละโรงงาน

## วิธีคิด

- `กำไร/รอบ = (ผลผลิต × ราคาขาย) − (วัตถุดิบ × ราคาซื้อ)`
- `กำไร/วัน = กำไร/รอบ × (86400 ÷ วินาทีต่อรอบ)`
- `% = กำไร/รอบ ÷ ต้นทุน`

ราคาซื้อ/ขายเป็นเรท swap ต่อ 1 หน่วย (marginal — ยิงที่ 1 หน่วย)

### ข้อจำกัดของตัวเลข

- ยังไม่รวม price impact เวลาซื้อ/ขายจำนวนมาก — pool ตื้น ราคาจริงจะแย่กว่าที่แสดง
- ยังไม่รวมค่า power และค่าอัปเกรดโรงงาน (ลงทุนครั้งเดียว)
- ราคาเป็น snapshot ณ เวลาที่ระบุบนหน้าเว็บ อาจเปลี่ยนไปแล้ว
- ทรัพยากรที่ pool แทบไม่มีสภาพคล่อง (เช่น `SCREWS`) จะมีราคาซื้อสูงผิดปกติ
  ทำให้โรงงานที่ใช้มันเป็นวัตถุดิบ (Acid, Bolts) แสดงกำไรติดลบมหาศาล


## โครงสร้าง

```
app/                 App Router — layout, หน้าเดียว, global CSS
components/          SummaryTiles (server) + ProfitMatrix (client, ลิสต์/ตาราง/ฟิลเตอร์)
lib/                 types, ตัวช่วยฟอร์แมตตัวเลข, ตัวโหลดข้อมูล
data/prices.json     ราคา snapshot + ตารางโรงงานทุกเลเวล
```

อัปเดตราคา = แทนที่ `data/prices.json` ด้วย snapshot ใหม่ (โครงสร้างตาม `lib/types.ts`)

## ราคา

หน้าเว็บดึงราคาใหม่ทุก 60 วินาที พร้อมนับถอยหลังและปุ่มรีเฟรชทันที แถบสถานะบอกเสมอว่า
ตัวเลขที่เห็นมาจากไหน — `สด` คือดึงจากต้นทางสำเร็จ `snapshot` คือใช้ไฟล์ที่ติดมากับ build

ต้นทางคือ GraphQL ของ craft-world.gg (`exactInputQuote`) เปลี่ยนปลายทางได้ด้วย `PRICE_API_URL`

API มีแต่ exactInput (ระบุจำนวนขาเข้า) จึงต้องยิงสองทิศต่อหนึ่ง symbol

| ต้องการ | ยิง | ได้ |
| --- | --- | --- |
| ราคาขาย `S` | `S → COIN` จำนวน 1 ชิ้น | COIN ที่ได้ = ราคาขายต่อชิ้น |
| ราคาซื้อ `S` | `COIN → S` ด้วย COIN เท่ากับราคาขาย | ได้ของ ~1 ชิ้น · ราคาซื้อ = COIN ที่จ่าย ÷ จำนวนที่ได้ |

ขาซื้อยิงด้วยมูลค่าราวหนึ่งชิ้นเพื่อให้ price impact เทียบเท่าขาขาย ถ้ายิงด้วย 1 COIN เฉย ๆ
ของแพงจะกลายเป็นรายการจิ๋วและได้ราคาดีเกินจริง สองทิศเป็นคนละ pool กันจริง — ใน snapshot
อัตราส่วน buy/sell กระจายตั้งแต่ 0.93 (DYNOKEY) ถึง 1.12 (PLASTICS) คำนวณย้อนจากค่าธรรมเนียมคงที่ไม่ได้

46 symbol × 2 ทิศ = 92 quote ต่อการรีเฟรชหนึ่งครั้ง รวมเป็น query เดียวด้วย GraphQL alias
แบ่งเป็นก้อนละ 24 (4 คำขอ) และ route แคชผลไว้ 30 วินาที หลายแท็บจึงไม่ถล่มต้นทาง

ราคาที่ได้ต้องครบทุกไอเทมที่สูตรใช้ ไม่งั้นถูกปฏิเสธแล้วตกกลับไปใช้ snapshot — payload
ที่ขาดบางตัวจะทำให้ต้นทุนกลายเป็น Infinity ทั้งกระดาน ซึ่งแย่กว่าราคาเก่า

## โมเดลต้นทุน

ปุ่มด้านบนหน้าเว็บสลับได้ 3 แบบ ตัวเลขทั้งหน้าเปลี่ยนตาม

| โหมด | วัตถุดิบมาจากไหน |
| --- | --- |
| `market` ซื้อวัตถุดิบ | ซื้อวัตถุดิบชั้นถัดไปจากตลาด คราฟต์ 1 รอบ ขายผลผลิตกลับ |
| `chain` คราฟต์สุดสาย | ซื้อเฉพาะ Dust · Fire · Water กับ Earth นอกนั้นคราฟต์เองทุกชั้น |
| `mixed` เลือกที่ถูกกว่า | แต่ละชั้นเลือกทางที่ถูกกว่าระหว่างซื้อกับทำเอง (make-or-buy) |

Earth เป็นเหมืองที่ขุดเองได้ แต่คิดราคาซื้อจากตลาดทุกโหมด เพื่อให้เห็นต้นทุนแบบซื้อจริง —
ถ้าคิดเป็น 0 ทั้งสาย Mud→Clay→Sand→Copper จะกลายเป็นฟรีและทำให้กำไรดูเกินจริงไปมาก

แต่ละเลเวลกางเป็น **รายการที่ต้องซื้อ** ได้ (`shoppingList` ใน `lib/cost.ts`) บอกว่าต้องซื้ออะไร
จำนวนเท่าไหร่ ราคาต่อหน่วยเท่าไหร่ ผลรวมเท่ากับต้นทุนของแถวนั้นพอดี กดที่เลเวลในตารางเพื่อเปลี่ยนแถวที่กางดู

โหมดที่คราฟต์เองสมมติว่าโรงงานที่ป้อนให้อยู่ที่เลเวลซึ่งกินวัตถุดิบต่อชิ้นน้อยที่สุด และ
**กำไร/วันยังหารด้วยรอบของโรงงานเป้าหมายอย่างเดียว** ยังไม่หักเวลาที่สายป้อนต้องใช้ —
เลขต้นทุนกับ % เชื่อได้ ส่วนกำไร/วันของสองโหมดหลังถือเป็นเพดานบน

## Responsive

เลย์เอาต์ปรับตามความกว้างจอด้วย CSS ล้วน ไม่มีการเช็ค user-agent (SSR จึงตรงกับ client เสมอ)

| ความกว้าง | เลย์เอาต์ |
| --- | --- |
| `< 760px` | ลิสต์บน/ตารางล่าง · ตารางเหลือ 4 คอลัมน์หลัก รายละเอียดที่เหลือย้ายลงแถว `.subrow` เต็มความกว้าง · แตะโรงงานแล้วเลื่อนไปตารางให้ พร้อมแถบ "← รายการโรงงาน" แบบ sticky |
| `760–899px` | คอลัมน์เดียว แต่ตารางแสดงครบ 9 คอลัมน์ |
| `≥ 900px` | สองพาเนล ลิสต์ sticky ค้างไว้ซ้าย · หัวตาราง sticky ขณะเลื่อนดูเลเวลยาว ๆ |

รายละเอียดอื่น: ปุ่มบนจอแคบสูงอย่างน้อย 40px, ช่องค้นหาใช้ font-size 16px กัน iOS ซูมเอง,
`:focus-visible` มองเห็นชัดสำหรับคีย์บอร์ด, hover เปิดเฉพาะอุปกรณ์ที่มีเมาส์จริง
และเคารพ `prefers-reduced-motion` ตอนเลื่อนหน้า

## CI

`.github/workflows/ci.yml` รันบน push เข้า `main`, ทุก pull request และตามกำหนดทุกสัปดาห์

- **build** — `npm run lint`, `npm run typecheck`, `npm run build`
- **audit** — `npm audit --audit-level=high` (ล้มงานเมื่อเจอช่องโหว่ระดับ high ขึ้นไป)
  พร้อมแนบผลเต็มไว้ใน job summary
